Persist the workflow state, wait for the reset, then resume from that state.

Handoff file: `~/.claude/${CLAUDE_SESSION_ID}-<description>.md`, where `<description>` is the task in 2 to 5 lowercase words joined by hyphens, e.g. `migrate-auth-to-oidc`.

1. If you are coordinating agent teammates, send each one this message now: "Usage limit near. Stop at the end of your current step and reply with a STATE REPORT: 1) your task in one sentence, 2) what is complete, with file paths and commit hashes, 3) what is in progress and its exact state, 4) the single next step, 5) anything the next run must know. Then do nothing more until you are relaunched." Wait for every report.
   Plain subagents started with the Agent tool cannot be messaged; wait for the ones you are waiting on to return, and treat their return value as their report.
2. Write the handoff file: the project directory, the overall task and goal, what is done, what is in progress, the next step, decisions taken, open questions, and one section per agent containing its type, the prompt you gave it, its STATE REPORT verbatim, and the exact prompt that relaunches it as a continuation.
3. Run `: >"$log" && ~/.claude/scripts/wait-for-usage-reset.sh 0 2>&1 | tee "$log"` in the background, with `$log` in the scratchpad directory and `dangerouslyDisableSandbox` set to true, then end your turn and do nothing else. The `0` means no cap, so the script sleeps until the window resets. It waits for whichever of the 5-hour and 7-day windows is over the threshold and resets last. Its completion notification wakes you. If the log ends with WAITING, run it again the same way. If it ends with ERROR, tell me the handoff file's path and stop.
4. When the log ends with RESET, run the script once more the same way, because the cache is rewritten only when the status line renders. A second RESET at once means every window is below the threshold; otherwise it sleeps again and you end your turn. Then read the handoff file, relaunch each agent with its continuation prompt, and continue. Delete the handoff file when the workflow is finished.
5. Start the watcher again so the next window is handled too: run `: >"$log" && ~/.claude/scripts/persistent-watch.sh ${CLAUDE_SESSION_ID} 2>&1 | tee "$log"` in the background, with a fresh `$log` in the scratchpad directory and `dangerouslyDisableSandbox` set to true, and follow its output when its completion notification arrives. The sandbox denies writes to the scratchpad directory, and the `: >"$log"` makes that fail before the watcher starts instead of leaving a watcher running with no log.
